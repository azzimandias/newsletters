# Рассылки ERP

React + Ant Design + Vite. Дизайн повторяет плотный рабочий интерфейс проекта repairs.

## Запуск

```powershell
npm ci
npm run dev
```

Открыть http://localhost:3009. Адрес Laravel задаётся в `.env`: `VITE_API_BASE_URL=http://localhost/api/mailings`. Запросы идут напрямую, без порта фронтенда и без Vite proxy. После изменения `.env` перезапустите dev-сервер; для production пересоберите приложение.
Авторизация использует существующую cookie `jwt` ERP, запросы выполняются с credentials. Для разработки вход в ERP и фронтенд должны использовать одно имя хоста (например, оба localhost). В production размещайте приложение на домене ERP либо настройте разрешённые CORS origins и cookie на сервере.

## Возможности

- Кампании: создание, копирование, черновики, подготовка аудитории, тест, запуск по московскому времени, пауза, возобновление, отмена.
- Визуальный конструктор писем и HTML, персонализация, шаблоны, общие вложения.
- Фиксированные и динамические списки; основной и старый справочники ERP; исключения, отписки, дедупликация на сервере.
- Отправители от компании или менеджера, SMTP-подключения, блокировки адресов.
- Получатели, статистика и журнал. Открытия и клики являются приблизительными метриками.
- Права и доступные компании получаются из `/api/mailings/session`; все операции дополнительно проверяются Laravel.

## Backend

Используется `/api/mailings` проекта `../erp_arstel`. В этой итерации добавлены session/options для интерфейса и число конфликтов подготовленной аудитории.
Перед работой с настоящими данными необходимы миграция модуля, права ACL, SMTP, публичный HTTPS URL и фоновые процессы из `../erp_arstel/docs/mailings-backend.md`.
Миграция рабочей базы и включение реальной отправки автоматически не выполнялись. Без готовой схемы API вернёт ошибку; интерфейс показывает её и позволяет повторить запрос.
Запуск рассылки разрешается только после проверки теста для актуальной версии. Изменения требуют новой подготовки и теста. Неизвестные результаты SMTP не отправляются повторно автоматически.

## Проверка и сборка

```powershell
npm test
npm run build
```

Готовая сборка — `dist`. Для размещения в `/newsletters/` установите `VITE_BASE_PATH=/newsletters/` перед сборкой. Значения VITE являются публичными: не хранить в них секреты.

## Автономная демонстрация

```powershell
npm run build
node tests/preview-server.mjs
```

Открыть http://127.0.0.1:4175. Это локальный стенд с вымышленными данными в памяти: он не подключается к ERP и не отправляет письма. После перезапуска изменения сбрасываются. Не использовать этот сервер для production. Загрузка файлов и настоящая отправка проверяются только с настроенным Laravel.
